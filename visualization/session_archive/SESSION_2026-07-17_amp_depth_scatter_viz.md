## What the figure shows

Scatter of all **525 KS4 units**: **x = spike amplitude (µV, log axis)**, **y = probe
depth (µm)**. Two panels differ only in the colour axis:

- **Panel A — mean firing rate** (Hz), **log** colour axis, **viridis**.
- **Panel B — waveform trough-to-peak duration** (ms), linear 0–1 ms, **red→green**
  (RdYlGn): **red = 0 ms (short / narrow-spiking)**, **green = 1 ms (broad-spiking)** —
  colours chosen per the user's explicit request.

Both panels shade the **z > 4850 µm artifact band** (dashed line + gray span) per the
2026-07-15 reclassification — units are still plotted, not dropped (see scope note).

### Data facts this relies on (verified this session)
- **`metrics.npz`** already holds the validated per-unit metrics (525 units):
  `amp_uV`, `fr`, `peak_depth`, `peakch` (0-based), `counts`, `uids`, and scalar `dur`
  (= recording length 6225.07 s). Amplitude is the validated
  `ptp(templates @ whitening_mat_inv) * gain` on the peak channel (gain 3.02734375 µV/bit,
  fs 30000); depth = `channel_positions(peakch, 2)`. These are **imported, not recomputed.**
  Generated by `sandbox\analysis\compute_metrics.py`.
- **`qc.npz`** (not used by this figure, but available via the same `readNPZ`) has the QC
  flags: `strict` (185), `rescued` (194), `rp_pass`, `isi_viol`.
- **Trough-to-peak duration is the one thing computed on the MATLAB side**, from
  `templates.npy` (525×61×383) and `whitening_mat_inv.npy` (383×383): for each unit, take
  the un-whitened waveform on its peak channel `wf = templates(u) * winv(:,peakch)`, find
  the trough (global min), then the first positive peak after it; `dur = (peak−trough)/fs`.
  **Observed range 0.10–1.13 ms, median 0.57** → the 0–1 ms colour range is a good fit
  (98% of units inside it; 10 units >1 ms clip to green). Python and MATLAB produce
  identical numbers, confirming the import path is faithful.

### Value ranges (both languages agree)
`amp 28–494 µV · depth 15–5730 µm · fr 0.004–64.3 Hz · dur 0.10–1.13 ms · n(z>4850)=61`.

## The `.npz` importer (`readNPZ`, main reusable addition)

`.npz` = a (uncompressed) zip of `.npy` members. `readNPZ` extracts to a `tempname`
folder (auto-cleaned via `onCleanup`), reads each member with the project's `readNPY`,
and returns a struct with `matlab.lang.makeValidName` field names (`s.amp_uV`,
`s.peak_depth`, …). Requires `readNPY` on the path. This is the general bridge for
pulling any Python-side `.npz` product into the MATLAB QC tools.

`qcAmpDepthScatter.m` `addpath`s `../io` off its own `mfilename('fullpath')` so `readNPY`/
`readNPZ` resolve regardless of the cwd.

Also self-contained in the script (no toolbox colormaps): `viridisMap` and `rdYlGnMap`
build the two colormaps by interpolating matplotlib's anchor stops to 256 colours.
